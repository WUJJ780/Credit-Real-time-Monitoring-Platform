# 信贷监管合规审查

商业银行零售信贷受严格监管。任何涉及定价、授权、用途的代码/策略变更，
在合入前按本清单逐项核对；演示环境同样要保证口径正确。

## 检查清单（与系统合规规则一一对应）

### 1. 利率合规（红线，不可放宽）

- 年化利率 ≤ 4 倍 LPR（当前 `rs.LPR_1Y * rs.RATE_CAP_LPR_MULTIPLE` = 13.8%，司法保护上限）
- 年化利率 ≤ 24%（两线三区绝对上限）
- 双线同时生效；定价 = 1年期LPR + 等级加点（A+2.5/B+3.5/C+5.0/D+7.0，E级不予准入）
- 检查点：`config/risk_strategy.py` 的 `GRADE_SPREADS` / `RATE_CAP_*`；
  规则在 `rule_engine.py`「利率4倍LPR合规」「利率24%合规」；提示词口径同步于 `resume/prompts.py`
- 禁止：服务费/砍头息等变相抬高实际利率的费用（产品文档须声明"除利息外无任何费用"）

### 2. 资金用途合规（一票否决）

- 禁止领域关键词：`PROHIBITED_PURPOSE_KEYWORDS`（股票/炒股/期货/虚拟货币/数字货币/购房/首付/赌博/民间借贷）
- 命中即合规一票否决：原 APPROVED 改 REJECTED 并清空额度利率（`middle_platform_agent.finalize` 实现）
- 检查点：用途说明（memo）与用途枚举（purpose）都要过 `contains_keyword` 规则

### 3. 个人信息保护（PIPL）

- 个人信息处理必须获得本人授权（`privacy_consent`）
- 征信查询必须经本人授权（`credit_authorization`）
- 未经授权查询征信 = 违规（规则「征信查询授权」，VIOLATION）
- 演示数据必须虚构（README「合规与安全提示」声明），不得使用真实个人信息

### 4. 审计留痕（监管报送基础）

- 拒绝决定必须保留完整理由（规则「拒绝留痕」）
- 全流程审计事件链完整（规则「审计留痕完整性」，audit_count ≥ 3）
- 每笔决策留痕：`output/<申请单号>_decision.json` + MinIO 审计件 + 消息总线事件
- 每个 Agent 的决策记录生效层（LLM推理/规则引擎/默认兜底）——降级路径可审计

### 5. 上线前必做（README「合规与安全提示」）

- 实际投产前需**法务合规评审与监管报备**
- 数据加密存储与传输
- 策略上线走灰度发布（按渠道/客群分流）

## 评审操作

1. 若服务在运行：提交合规场景测试（用途=股票 → REJECTED；利率超限 → 一票否决）
   `POST /api/v1/demo?cases=compliance` 或表单页填"股票投资"用途
2. 读代码核对：规则定义（rule_engine.py）↔ 策略配置（risk_strategy.py）↔ 提示词（resume/prompts.py）
   三处口径必须一致
3. 检查变更 diff 是否触及 `PROHIBITED_PURPOSE_KEYWORDS` / `RATE_CAP_*` / 授权相关规则——
   触及则**标注高风险，建议人工复核**

## 常见坑

- 只在演示环境验证就宣称"合规通过" → 演示与生产的合规要求不同（生产需报备）
- 修改 `RATE_CAP_LPR_MULTIPLE` 或删减禁止用途关键词来"让案例通过" → 监管红线不可动
- 新增 Agent 但没接审计留痕 → 破坏审计链完整性
- 提示词里教 LLM 放宽合规口径 → LLM 层与规则层口径漂移（提示词必须引用配置常量）
