# 风控决策解读

银行风控决策必须**可解释**（监管要求 + 客户投诉处理）。本技能教你从系统里取出
一笔申请的全部决策依据，翻译成业务语言。

## 取数方式（三选一）

1. **API**（服务运行时）：`GET http://127.0.0.1:8000/api/v1/applications/{申请单号}`
   返回：状态、耗时、`final_decision`（决策/额度/利率/理由链/反欺诈分/信号标签/合规标记）、`audit_events`（全流程审计时间线）
2. **审计文件**：`output/<申请单号>_decision.json`（CLI 运行留痕）
3. **前端**：监控台对应卡片展开详情（理由链/环节链路/审计时间线）

## 解读框架（按此顺序，从结论到证据）

### 1. 结论层 —— final_decision.decision

- APPROVED / REJECTED / MANUAL_REVIEW / SUPPLEMENT
- 附 `final_amount`（额度）、`final_rate`（年化利率）、`fraud_score`（反欺诈分 0-100）、`fraud_tags`（命中信号）

### 2. 理由链 —— final_decision.reasons（按环节顺序）

| 理由关键字 | 业务含义 |
|---|---|
| 综合风险分X低于/超过自动通过线 | 审批决策：三环节加权风险分（反欺诈30%+信用45%+进件25%）与35/65阈值的比较 |
| 进件审核拒绝：准入拒绝 | 年龄/收入/金额/期限不符，或**三要素核验不通过** |
| 资料不完整，需补件 | 缺资料（权重：身份证正25/反25/收入证明30/人脸20） |
| 反欺诈拒绝/命中信号 | 黑名单（司法/失信55分）、多头、设备ROOT/模拟器/代理、团伙关联、相似欺诈案件 |
| 信用硬拒绝 | M3+逾期、M2≥2次、收入负债比>75%、信用等级E |
| 转人工复核 | 反欺诈MEDIUM/HIGH、信用等级C/D、DTI超55%、灰色区间（保守策略，非拒绝） |
| 合规违规一票否决 | 利率超4倍LPR(13.8%)/24%、用途涉股票/购房等禁止领域、未授权 |

### 3. 证据层 —— audit_events 时间线

每条审计事件：时间 → Agent → 决策层（LLM推理/规则引擎/默认兜底）→ 结论。
逐环节核对证据链是否完整（合规要求审计事件链完整）。

### 4. 输出格式（对客户/业务方解释）

```
结论：❌ 审批拒绝
原因（按环节）：
  1. 进件审核通过（资料齐全，三要素一致）
  2. 反欺诈命中信号：设备已ROOT/越狱（+20分）、模拟器环境（+15分）→ 欺诈分80 SEVERE
  3. 触发自动拒绝规则（反欺诈一票否决）
后续：可在XX天后重新申请，或转人工审批岗申诉复核
```

## 业务口径要点

- **MANUAL_REVIEW 不是拒绝**：是保守策略（宁可转人工不可误放行），1-3 个工作日人工裁决
- **SUPPLEMENT 不是终局**：补齐资料可重新受理（智能助手可代办补件闭环）
- **合规一票否决**：利率/用途/授权类违规，即使其他环节全通过也拒绝
- **欺诈分是信号分不是概率**：80 分以上才自动拒绝（SEVERE）
- 演示数据的 Mock 身份只有注册表内 5 个（如 王小明/110101199503123456/13800000001），
  自定义身份必然「三要素核验不通过」被拒——解读时要说明这是演示环境的核验注册表限制

## 常见坑

- 只看 reasons 第一条就下结论 → 理由链是按环节顺序的完整证据，必须全读
- 把「转人工复核」说成「被拒」→ 客户投诉风险
- 把 fraud_score 解释成"欺诈概率80%" → 是风险信号评分
- 演示环境数据（Mock黑名单/征信）与真实生产数据混谈 → 解读时注明数据来源
